# 要件定義

目的： AWS Healthのイベントを自動検知し、Amazon Bedrock（AI）で要約した内容をBacklogの「課題（チケット）」として自動起票する。

## 機能要件

- イベント検知
  - AWS Healthの全イベント（障害、スケジュールされた変更、通知）をEventBridgeでリアルタイムに検知すること。
- AI要約（Amazon Bedrock）
  - イベントに含まれる英語の通知原文（Description）を読み込み、Claudeを用いて日本語で要約すること。
  - インフラエンジニアが即座に判断できるよう、「概要」「緊急度」「対応策」の3項目に絞って抽出すること。
- Backlog自動起票
  - 指定されたBacklogプロジェクトに対して、自動で「課題」を作成すること。
  - イベント名（eventTypeCode）を課題タイトル（件名）として起票すること。
  - 本文は「Backlog記法」に準拠し、各大見出し・中見出しの上下に適切な空行を挟んで視認性を高めること。
  - 要約だけでなく、対象のリソースID、発生リージョン、および英語の通知原文（詳細ログ）も網羅して記録すること。
  
## 非機能要件

- セキュリティ（認証情報の保護）
  - BacklogのAPIキー、スペースID、プロジェクトID等の機密情報はソースコードに直書きせず、環境変数（.env / Lambda環境変数）で安全に管理すること。
- マルチリージョン連携
  - Lambdaを東京リージョン（ap-northeast-1）に配置しつつ、Bedrockの呼び出し（クロスリージョン推論等）を正常に行えること。
- 保守性・ログ管理
  - 処理の成否やエラー発生箇所（EventBridgeパース、Bedrock呼び出し、Backlog API通信）が追跡できるよう、適切な例外処理とCloudWatch Logsへのログ出力を実装すること。
- コスト・タイムアウト最適化
  - Bedrockの呼び出し遅延や無限ループによる予期せぬ課金を防ぐため、Lambdaのタイムアウト時間を適切に設定すること。
  - 平時の維持コストを0円とし、イベント発生時のみ課金される完全従量課金構成とすること。

## 使用サービス・ツール

- AWS
  - AWS Health, Amazon EventBridge, AWS Lambda, Amazon Bedrock, IAM
- 外部サービス
  - Backlog (API v2)
- 開発・管理ツール
  - AWS CDK, Python, uv
